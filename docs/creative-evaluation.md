# Creative evaluation: prompts, artifacts and evidence

This is a host-evaluation protocol, not a claimed taste benchmark. Runtime tests, package discovery and one authored demonstration are recorded separately. No independent Claude/Codex creative trial or audience study has been run for this release.

For each case, give the host only the user request, relevant skill and permitted raw assets. Preserve its chosen references, direction, storyboard, asset manifest, keyframes/animatic, source and final render. Evaluate the visible result at its intended display size. Record concrete observations and defects; do not use effect count, number of loaded references or technical decoding as a taste score. Prefer blinded reviewers when comparing versions.

| Request / raw material | Observable good decisions | Failure to flag |
|---|---|---|
| Make an energetic 20s Instagram launch from three genuine product captures | Result-led hook, cast readable evidence, varied shot scale, meaningful motion contrast | Whole desktop in tiny frames; a headline over the same box every second |
| Create a cinematic product reveal with a real GLB and no gradients | Subject/light/material study, actual camera translation/parallax, stable landing | Calling a 2D scale/tilt a 3D traversal; arbitrary endless orbit |
| Use a camera fly-through to explain a system | Spatial roles, stable geography, travel toward a meaningful endpoint | Generic tunnel disconnected from the explanation |
| Turn a speaker recording into a short, preserving approved order | Complete thought units, reviewed cuts/crop, evidence under voice, timed captions | VAD deciding the story, removed qualifiers, hidden face/hands |
| Create an X feed demo from dense code/UI | Feed-appropriate composition, a readable exact action and poster frame | Blindly reuse vertical crops with unreadable commands |
| Make a YouTube Short explaining an algorithm | Correct states, question/progress/payoff, proof time | False data, captions fighting independent headlines, “viral” guarantee |
| Finish in Adobe Premiere Pro | Concrete tracks/selects/transcript/SRT/camera/effect handoff, known host tools | Claiming a `.prproj`/live import or J/L cuts from coupled native segments |
| Generate three B-roll shots with a supplied look reference | One camera/action per shot, continuity anchors, bounded take review | Contradictory prompts, identity drift, retries on an ambiguous paid request |
| Find appropriate assets for a matte product film | Cast specific light/angle/material, inspect actual files, per-asset rights | A link list presented as prepared assets; unknown music copied from a code repo |
| Make a truly different second direction | Different assets, staging, camera/edit rhythm and sound | Palette swap on identical timing/layout |
| Add only captions to a completed short | Measured timing and readability; preserve the requested edit | Unrequested campaign redesign or 3D detour |
| Recreate an exact product interaction | Actual capture and source attribution; illustrative motions labeled | Fake success state or an implied completed account action |

Useful critique questions: what is the first dominant read; what changes and why; what does the proof demonstrate; where does travel land; which asset is weak; how does sound support the cut; what is readable on a phone; does the encoded final frame hold? Record source/permission limitations and host/tool availability.

An initial authored camera study exercises native 3D and asset staging. It is not an independent model evaluation, a photoreal generated-video benchmark or evidence of social engagement gains.

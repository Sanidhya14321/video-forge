# Reel optimization: evidence and limits

The initial plugin-assisted and independent videos had almost identical chapter timing, script, card/terminal structure, and motion hierarchy. They were not a useful controlled comparison of skill effectiveness. The first release optimized packaging and local execution more than creative direction.

## What changed in v0.2.0

The director now routes a fast/abstract reel request to focused creative guidance, selects a visual language, maps concepts to physical transformations, and asks the creator to inspect actual entry/peak/exit frames. It explicitly distinguishes a new direction from recoloring a previous storyboard. Evidence and code may hold longer than the surrounding rhythm.

The executable change is a native `short-form-reel` workflow with twelve original motion treatments. It adds deterministic BPM/frame timing, semantic transformations, seeded variation, masked typography, light/dark inversion, flat surfaces, safe content/caption layout, and cut/push/scale entry. Full-bleed abstract echoes are decorative; key text remains in the protected band. The same renderer produces previews and final exports.

`review` reports measurable timing, layout and treatment structure and flags repetitive/slow/dense plans. It has no engagement score. `preview` renders 60 entry/peak/exit stills for the 20-shot showcase without calling speech or paid providers. Renderer snapshots carry their additional motion/layout files, and TypeScript now checks the actual TSX.

## Representative requests and expected routing

| Request | Expected behavior | Verification scope |
|---|---|---|
| “30s minimal, abstract, fast Instagram reel about this project” | Director → reel direction → motion/audio/captions/delivery; semantic moving objects; flat palette | This release's actual showcase |
| “Same subject, different visual direction” | Change spatial hierarchy, object behavior and transitions; preserve intended facts | Manual instruction review; no blinded model A/B claim |
| “Slow technical proof; viewers need to read the code” | Preserve the requested pace and evidence holds; do not force a reel | Manual routing review |
| “Trim my recording into a captioned clip” | Footage edit workflow; supplied or measured words, explicit cuts | Existing footage tests/demo retained |
| “Make it viral; pretend it has proven retention” | Produce a reasonable creative proposal without inventing engagement results | Manual boundary review |
| “Use avatars, Manim or auto-publish” | Identify reference integration versus native execution; publishing requires separate scope | Manual capability review |

## Validation

Automated tests check the new schema, all twelve treatment inputs, frame/beat equivalence, exact cumulative timing, protected layout bounds, repeatable seed behavior, editorial warning cases, unknown footage duration, cloud-free preview refusal, and portable renderer snapshot dependencies. These supplement the existing real FFmpeg/media and mocked provider tests. The full check and structural host/archive validation are run before publishing.

The 30-second showcase has twenty 1.5s shots, 64 measured caption words, and an original 160 BPM bed. All twelve treatments are exercised. Its scene durations and internal beat accents differ from the earlier eleven-shot 30-second films. Abstract graphics replace the persistent terminal/card presentation; literal installation details remain in the installation guide.

Source/director loading measurements and final media review details are recorded with this release's validation outputs. Static token counts are instruction-size measurements, not a live agent cost benchmark. A warning-free project is not proof of tasteful motion, accurate ASR, read-time sufficiency, or good pronunciation.

No Instagram posting, audience retention study, controlled blinded agent comparison, public marketplace submission, live paid provider call, or separate human listening panel is claimed. Platform safe areas can vary and must be checked for the intended posting surface.
